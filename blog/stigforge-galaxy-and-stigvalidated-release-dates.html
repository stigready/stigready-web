StigForge on Ansible Galaxy and stigvalidated: release dates

We have set target dates for two releases. These are targets, not promises: if a date moves, we will update this post with the new date and the reason. Neither release is live today.

Update, 2026-11-26: both releases move earlier, and each now goes out one piece at a time instead of all at once. We first set Tuesday, December 8 for Galaxy and Thursday, December 17 for stigvalidated. We are now working to release as soon as possible: each role goes to Galaxy as soon as it has passed its own checks, from about November 29, and each stigvalidated repository goes public as soon as the images for its role have passed theirs, from about December 3. Nothing waits for the slowest one. Until all eight are out, we will name only the ones that are live, and this post will say which.

StigForge roles on Ansible Galaxy

StigForge roles are Ansible roles that apply DISA STIG or CIS Benchmark settings to a Linux host. They are public on GitHub today, one repository per operating system and benchmark, such as stigready/rhel9-stig and stigready/ubuntu24-cis. On 2026-11-23 the newest tag on each is v0.3.51.

We plan to publish the roles to the stigready namespace on Ansible Galaxy, so you can install them with ansible-galaxy role install at a pinned version. This release covers the eight roles we use to build StigReady Applied images: rhel8_cis, rhel8_stig, rhel9_cis, rhel9_stig, rhel10_cis, rhel10_stig, ubuntu24_cis and ubuntu24_stig. The other role repositories (Amazon Linux 2023, CentOS Stream 9 and 10, Debian 12, Oracle Linux 9 and 10, and Ubuntu 22.04, plus the stigready-baseline role) are not part of this release: they stay on GitHub at their current tag. All eight will be version 0.3.57. We will publish a role on Galaxy only after a StigReady image built with that exact version has passed our OpenSCAP gate, so each role goes live when its own images have passed, not on one shared day. Each announcement will name only the roles that are live.

stigvalidated test profiles

stigvalidated is a second set of tests for each StigForge role: a CINC Auditor profile with a test for each SSG rule the role applies that has an OVAL check, written from that check. It is separate from the OpenSCAP scan, so the two can be compared rule by rule.

We plan to make the profiles for the same eight roles public on GitHub, one repository at a time, generated from release 0.3.57 of those roles, the version we plan to publish on Galaxy. That release is not tagged yet: the newest tag today is v0.3.51. We plan to license our code and packaging in them under Apache-2.0, and the content that comes from the SCAP Security Guide (SSG) under BSD-3-Clause. A repository goes public only after every StigReady image built with its role at 0.3.57, on each operating system and architecture we ship for that role, has built cleanly on its first attempt, and its tests and the OpenSCAP scan agree on those images. Support will be best effort, through GitHub issues on each repository.

What could move a date

Keeping our AWS Marketplace images current comes first, and both releases share build capacity with that work. Each role and each repository also has checks it must pass before it goes out. We will not skip a check to keep a date. If a date moves, this post will say so, with the new date and why.

Until then

You can use the roles from GitHub today, pinned to a tag. Test them on a non-production host first: the current tag, v0.3.51, has known open issues, and their fixes are planned for release 0.3.57, the version going to Galaxy. These how-tos show how:
